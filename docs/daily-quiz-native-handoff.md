## 1. What the trainer experiences (replicate exactly)

1. The trainer signs in and lands on the dashboard. The app calls `quiz_my_state()`. The popup is **due** when the state is missing, or a question is in progress (`current_question_id` set), or `next_quiz_eligible_at` is null or in the past. That check is re-run every minute while the dashboard stays open, so the next question appears 3 hours after the previous one without a reload.
2. The popup opens over the dashboard, no close button, no outside tap, Android back does nothing. Header "Daily Quiz · Test your knowledge", an "Attempt N of 3" pill, a flame badge with the current streak, and once the streak is above 0 a bar "Current Streak … Best: N". Then the question and four option rows A to D. **Submit Answer** enables once an option is chosen (it reads "Submit Answer (2 left)" after a miss).
3. A wrong guess that leaves attempts: an amber banner "Not quite. 2 attempts left." with "The answer stays hidden. Pick another option."; the option just tried turns red with a cross and cannot be picked again; the selection clears; the pill counts up. Nothing reveals the answer.
4. The question is over on a correct guess or the third miss. Correct: a green banner "Correct, first try!" or "Correct on attempt N", a "+3 / +2 / +1 points" chip, "N streak" when above 1, the correct option green. Missed: a red banner "Out of attempts", "Answer: C. <text>" (this is the only time the answer is shown), the correct option green, the trainer's wrong picks red. Both show "Next question in 3 hours". The footer button becomes **Continue to Dashboard**.
5. Footer stats line: "Best: N" and "Today: N right · N wrong · N guesses".
6. Other popup states: "Loading your quiz..."; "Your next question is due in 2 h 16 min." with Continue (the server said not due yet); "No quiz questions available." with Continue; an error state with the server message, **Try again** and Continue. The trainer is never trapped by a backend fault.
7. Reopening the app mid-question brings the same question back with the guesses already used ("Welcome back. 2 attempts left on this question.") and the tried options greyed.
8. Dashboard tile **Quiz Streak**: the streak, "in a row", "🔥 On Fire!" from 3, otherwise "Today N right · N wrong". Trainers only.
9. Dashboard card **Quiz Leaderboard**: This month / Last month toggle, sub-header "3, 2 or 1 points by the guess that got it right · accuracy = mean of daily right %", the top five with rank medals, name, "N right · N wrong · N guesses", a flame with the streak from 3, an **accuracy chip** ("55%" over a tiny "ACCURACY" label; green from 75, amber from 50, rose below, "n/a" in grey until a question is finished; long-press or tooltip "Mean of N daily scores"), and points; the viewer's own row highlighted, and shown again under "· · ·" when outside the top five; empty state "No answers this month yet".

## 2. Backend contract (live, consume as is)

Tables: `mcq_questions_for_trainers` (question bank; `correct_option` is **not readable** by signed-in users any more, only inside the RPCs), the **new `daily_quiz_score`** (one row per trainer per **IST** day, UNIQUE `(trainer_id, quiz_date)`, columns `id, trainer_id, quiz_date, details jsonb, created_at, updated_at`; **everything about the day lives in `details`**: `{ correct, wrong (questions resolved that day), attempts (guesses that day), points, streak (the running streak after the day's last resolved question), questions: [ { id, result: "correct" | "wrong", attempts: 1..3, points: 0..3, at } ], current_question_id, current_attempts, current_wrong_options: string[] (the question in progress, on the trainer's newest row), last_question_at, next_quiz_eligible_at (the 3-hour clock, newest row), accuracy (the day's score, integer 0..100 = round(100 * correct / (correct + wrong)), absent until a question is resolved; migration `20260923120000_daily_quiz_accuracy.sql`) }`), and `trainer_certificates` (a row named `CSPS` picks the CSPS category, else ACE; questions tagged `ALL` are served to everyone). The old `trainer_quiz_scores` table still exists but is **not used** any more; never read or write it.

RLS on `daily_quiz_score`: trainers read their own rows, admins every row, **nobody writes** except the RPCs (SECURITY DEFINER). The app does not need to read the table at all: `quiz_my_state()` gives everything the screens show. Only the four entry RPCs below are callable by signed-in users; the internal helpers (`quiz_state_for`, `quiz_today_row`, `quiz_category_for`, `quiz_question_json`, `quiz_new_day_details`) return `42501 permission denied` over PostgREST by design, so never call them.

RPCs (all `SECURITY DEFINER`, granted to authenticated; wrap each in `withTimeout`, 6 to 8 s):
- `quiz_my_state()` → `{ current_streak, longest_streak, total_correct, total_questions, total_attempts, next_quiz_eligible_at, last_question_at, current_question_id, today: { correct, wrong, attempts, points } }` (newest row's streak and clock, max streak, sums over all rows, today's row). This is what decides whether the popup is due and what the tile shows.
- `quiz_next_question()` → `{ eligible: true, resumed, question: { id, question, option_a, option_b, option_c, option_d, category }, attempts_used, attempts_left, wrong_options: string[], state }` when a question is ready (it creates today's row on first use, marks the question in progress, prefers questions not served in the last 30 days); `{ eligible: true, question: null, state }` when the bank is empty for the category; `{ eligible: false, next_quiz_eligible_at, state }` when the 3-hour clock is still running. **Side effect**: never call it from a list or a cache warmer; only when the popup is about to show, and ask again each time the popup opens.
- `quiz_submit_answer(p_question_id uuid, p_option text)` with `p_option` in `a | b | c | d` → `{ repeat, correct, resolved, attempts_used, attempts_left, wrong_options, points_awarded, correct_option, correct_text, state }`. `repeat: true` means the same wrong option was sent again (not counted). `correct_option` / `correct_text` are non-null **only** when `resolved` and not `correct`. Errors to surface verbatim: "Pick one of the four options", "No question in progress; ask for a new one" (call `quiz_next_question` again), "That question is gone; ask for a new one".
- `get_quiz_leaderboard(p_month date)` (any date in the month; `null` = this month, IST) → rows `{ rank, trainer_id, trainer_name, month_points, month_correct, month_wrong, month_attempts, month_questions, current_streak, longest_streak, total_correct, total_questions, month_accuracy, month_days }` ordered by rank (month points, then longest streak, then total correct); trainers with `profiles.role = 'trainer'` only. `month_accuracy` (integer, `null` until a day is played) is the **mean of the trainer's daily scores** over the month's played days, where a day's score is `details.accuracy = round(100 * correct / (correct + wrong))` (4 questions and 2 right = 50; a 50 day then a 60 day = 55, the mean of days, not the ratio of totals); `month_days` is how many days were averaged.
- `state` in the replies is the same object as `quiz_my_state()`.

Rules the server enforces (the app only mirrors them for display): three guesses per question; points 3 / 2 / 1 by the guess that got it right, 0 for a miss; a correct guess extends the streak, a resolved miss resets it to 0, the longest streak is the max over rows; a guess and a resolution are written to **today's** row (a question started before midnight IST moves to the new day); both outcomes set `next_quiz_eligible_at = now() + 3 hours`; a question served in the last 30 days is not repeated unless every question has been.

# Essentials Auction: bids by questions (Android handoff, 2026-10-10)

The web auction changed from "first press wins" to "best answers win". The Android page (`android/trainer/essentials-auction.md`) must follow; the backend is shared and already decided. Nothing for Android to run on the server.

## What changed in one paragraph
Pressing a lot no longer books it. It opens the client's five questions (3 from the week's training summary, 2 from the health context), one at a time, each answered once. On submit the server scores them (1 point per right answer) and stores the bid with the time. At 4:00 PM IST a cron decides every lot: highest points wins, equal points the earlier bid, still equal the client's usual trainer; the winner's `session_schedule` row, care-team note and My Crew entry are written by the server. Every trainer who bid sees a won / lost card for 4 hours. A trainer may bid on several lots a day. Losers see the winner's name and points. The old `grab_essentials_session` now always raises "Sessions are now won by answering the client's questions in the auction. Update the app and press Answer and bid." so an old build fails politely.

## RPCs (migration `20261010120000_essentials_auction_bids.sql`, all `authenticated`)
- `get_essentials_auction(p_date)` keeps every old column and adds: `bids_count int`, `question_count int`, `my_points int|null`, `my_submitted_at timestamptz|null`, `winner_trainer_id uuid|null`, `winner_name text|null`, `winner_points int|null`, `round_result text|null` (`won` | `booked_elsewhere` | `no_bids` | `no_winner`), `evaluated_at timestamptz|null`. `status` is unchanged: `grabbed` once a session row exists (after 4 PM the winner's), `reserved` during the usual trainer's 30-minute head start, else `open`.
- `get_essentials_auction_quiz(p_client_id uuid, p_date date default tomorrow) -> jsonb` `{client_id, training_date, blocked: text|null, questionnaire_version, question_count, questions: [{n, source: 'weekly'|'context', question, options: [4 strings]}], already_bid: bool, my_bid: {points, submitted_at, correct: bool[]}|null, bids_count}`. `blocked` is the database's plain sentence when the caller may not bid right now (window closed, reserved for the usual trainer, already booked, has the client today, wrong role); show it instead of the questions. `question_count` 0 means no questionnaire on file: show "No questions yet, earliest bid wins" and let the trainer submit an empty answer list.
- `submit_essentials_bid(p_client_id uuid, p_answers int[], p_date date default tomorrow) -> jsonb` `{client_id, client_name, training_date, slot_time, modality, points, question_count, correct: bool[], submitted_at, bids_count}`. Answers are 0-based option indexes, one per question, in order; the array length must equal `question_count`. Raises plain sentences: the same checks as the old grab, plus "You have already answered for this session. One attempt only." and "This auction has been decided."
- `get_my_auction_results(p_hours int default 4) -> table` `(round_key text, client_id, client_name, training_date date, slot_time, modality, won bool, result text, my_points int, question_count int, my_submitted_at, winner_trainer_id, winner_name, winner_points, bids_count int, session_id, evaluated_at)`: the caller's rounds decided in the last N hours. Poll every 5 minutes on the dashboard and on focus; the server stops listing a round after the hours pass, so no client-side expiry is needed.
